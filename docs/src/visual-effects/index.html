Prototype — not a package

One interface for generators and filters

AVVA's renderer synthesises images from uniforms. A CRT filter transforms an image it is given. Treated as different kinds of thing, the shader work in each stays stuck to the app it was written for. They differ in whether a pass samples an incoming image, and in nothing else.

inputs: { source?: boolean; feedback?: boolean }

A pass that sets source is a filter and receives uSrc. A pass that does not is a generator. The chain feeds each pass's output to the next either way, so the CRT pass below is the same object whether it is finishing a generated field or a video file you drop in.

The three passes

Three, because between them they cover every part of the interface. 

field   generator + feedback + compile-time defines.
        N_HUES is a #define, so moving the hues slider
        recompiles rather than branching per fragment.
        AVVA's shape.

bloom   filter + a private quarter-res ping-pong buffer
        + a four-step draw hook. Stands in for chladni,
        which needs the same three things and a
        262k-particle simulation besides.

crt     filter, single draw.

Two decisions in the CRT pass

Scanline density is a line count rather than a multiple of the resolution. Keyed to device pixels it would shift on a retina display and again on every resize, which is a strange property for a fixed number of scanlines to have.

Ghosting samples uPrev, which the chain supplies as this pass's own previous output. Sampling the previous input instead gives a one-frame echo: it looks similar for a frame or two and then stops, because nothing accumulates.

Curvature runs −1 to 1. The distortion is normalised by how far the corner moved, so the corners stay pinned to the frame and the sign is free to go either way — positive bulges the middle out, negative pulls it in.

Resolution

Every pass gets two. uRes is the buffer this pass renders into; uOutRes is the chain's final output. Anything keyed to signal resolution — grain, blur taps, bloom — wants the former, or a pass at scale: 0.5 quietly changes its own look. The bloom pass runs its bright-pass and blur at quarter res, which is where the distinction first bites.

Uniforms are typed by the program, not the caller

uniforms() returns a plain bag of names to values. A Float32Array is a float[] or a vec3[] depending on what the shader declared, and only the shader knows, so the chain reads the types back off the linked program. A pass may hand over more than a given step uses; names the compiler dropped are ignored.

No domain data anywhere

The params below are neutral: energy, motion, x, y, impulse. Here they come from a few LFOs. In AVVA they would come from an AudioFrame through a small adapter at the call site, and in a video tool most of them would sit at rest. The chain cannot tell which.

Slot colours divide the wheel into equal sectors of perceptual hue rather than display hue — the property @amplib/color exists to provide. Equal steps of HSV hue do not look equal, and a palette spaced that way comes out visibly lopsided.
